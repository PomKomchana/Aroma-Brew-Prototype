# Aroma Brew

ระบบจัดการร้านกาแฟและเบเกอรี่ (POS + สต็อกแบบตัดตามสูตร) เพื่อการออกแบบและการจัดการระบบฐานข้อมูล

ร้านมีหน้าขายหน้าร้านให้แคชเชียร์ หน้าจัดการสต็อก/สั่งซื้อให้พนักงานคลัง หน้ารายงานให้เจ้าของ และมีเว็บฝั่งลูกค้าไว้ดูเมนู สั่งล่วงหน้า และเช็กแต้มสะสม

## ใช้อะไรบ้าง

- Frontend: React 18 + TypeScript + Vite
- Backend / DB: Supabase (PostgreSQL) — logic หลักเขียนเป็น function ในฐานข้อมูล แล้วให้หน้าเว็บเรียกผ่าน `supabase.rpc()`
- Deploy: Netlify

ไม่มี server แยก (ไม่มี Node API) เพราะเรื่องสำคัญอย่างการตัดสต็อก การคิดแต้ม การคิดราคา ทำใน DB หมดแล้ว ข้อดีคือถ้าขั้นตอนไหนพัง transaction จะ rollback ทั้งก้อน ไม่มีบิลที่สต็อกไม่ถูกตัด

## วิธีรัน

1. สร้างโปรเจกต์ใน Supabase
2. เปิด SQL Editor แล้วรันไฟล์ใน `database/` ตามลำดับ **schema → functions → security → seed** (รายละเอียดและวิธีรันทีละไฟล์อยู่ใน [database/README.md](database/README.md))
3. เอา Project URL กับ anon key จาก Project Settings → API มาใส่ในไฟล์ `.env` (copy จาก `.env.example`)
4. ติดตั้งแล้วรัน

```bash
npm install
npm run dev
```

build สำหรับ deploy ใช้ `npm run build` (ตั้ง env สองตัวนั้นบน Vercel ด้วย)

## บัญชีทดลอง

| รหัสพนักงาน | รหัสผ่าน | บทบาท |
|---|---|---|
| 1 | owner1234 | เจ้าของร้าน |
| 2 | cashier1234 | แคชเชียร์ |
| 3 | stock1234 | พนักงานคลัง |

ลูกค้าตัวอย่าง: `0812345678`, `0898765432` (ใช้ทดสอบเว็บสมาชิกกับสั่งล่วงหน้า)

## หน้าจอ

อ้างอิงเลข S01–S18 จากสไลด์ Submission 2

**พนักงานหน้าร้าน (แคชเชียร์)**
- `/login` เข้าสู่ระบบ (S01)
- `/shift` เปิดกะ (S02)
- `/pos` ขาย เลือก modifier ค้นหาสมาชิก ชำระเงิน ใบเสร็จ (S03–S07)
- `/orders` คิวออเดอร์ และยกเลิกบิลในกะที่ยังเปิดอยู่ (S08)
- `/close-shift` ปิดกะ นับเงินสด (S09)
- `/preorders` รับออเดอร์สั่งล่วงหน้า เริ่มทำ → พร้อมรับ → รับของและชำระเงิน

**คลัง (stock / owner)**
- `/stock` สต็อก รับของเข้า ตรวจนับ ประวัติการเคลื่อนไหว ตั้งจุดสั่งซื้อและแจ้งเตือนใกล้หมด (S10–S12)
- `/suppliers` ซัพพลายเออร์ และวัตถุดิบที่แต่ละเจ้าส่ง
- `/purchasing` ใบสั่งซื้อ draft → sent → partial → received

**เจ้าของร้าน**
- `/dashboard` (S13), `/products` สินค้า/สูตร (S14), `/employees` พนักงาน (S15), `/promotions` โปรโมชัน (S16)
- `/reports` รายงานยอดขายรายวัน/เดือน/ปี/ช่วงเวลาเอง ดาวน์โหลด CSV ดูรายการบิล และ audit log (S17)

**ลูกค้า (ไม่ต้องล็อกอินพนักงาน)**
- `/`, `/menu`, `/allergens`, `/stores` ดูเมนู ข้อมูลสารก่อภูมิแพ้ สาขา
- `/signin` เข้าสู่ระบบด้วยเบอร์โทร + OTP แล้วดูแต้มที่ `/rewards` / `/member` (S18)
- `/basket` → `/my-orders/:id` สั่งล่วงหน้า แล้วไปจ่ายเงินรับของที่เคาน์เตอร์

**อื่น ๆ**
- Offline mode: ถ้าเน็ตหลุดระหว่างขาย ระบบเก็บบิลไว้ในเบราว์เซอร์ แล้วส่งขึ้นไปเมื่อต่อเน็ตได้ (NFR-04)

## กันไม่ให้ Supabase (แผน free) หยุดทำงาน

โปรเจกต์ Supabase แผนฟรีจะถูก pause ถ้าไม่มีการใช้ฐานข้อมูลประมาณ 1 สัปดาห์ ไฟล์ `.github/workflows/keep-supabase-awake.yml` เรียก `get_branches()` วันละครั้งเพื่อกันเรื่องนี้ วิธีเปิดใช้: เพิ่ม repository secret 2 ตัว (Settings → Secrets and variables → Actions) คือ `SUPABASE_URL` กับ `SUPABASE_ANON_KEY` แล้วทดสอบได้ที่แท็บ Actions กด "Run workflow"

GitHub จะหยุด workflow ที่ตั้งเวลาไว้ใน public repo ถ้าไม่มี activity ใน repo นาน 60 วัน ถ้าเกิดขึ้นให้กดเปิดใหม่ที่แท็บ Actions

## ที่ยังไม่ได้ทำ / ข้อจำกัดที่รู้อยู่แล้ว

- หน้าแก้ Modifier (ตอนนี้แก้ใน DB ตรง ๆ) ยังไม่มีในหน้า `/products`
- OTP เป็นแบบ demo: โค้ดจะโชว์บนหน้าจอเลย ยังไม่ได้ต่อ SMS/LINE
- ฟังก์ชันฝั่งพนักงานเช็กสิทธิ์จากรหัสพนักงานที่ส่งมา (ไม่ได้ใช้ Supabase Auth) พอสำหรับ prototype แต่ถ้าจะใช้จริงต้องเปลี่ยนเป็น session/JWT
- ยังไม่มีหน้าจัดตารางงานกับลงเวลา ทั้งที่ตาราง `attendance` และ `work_schedule` อยู่ใน ERD แล้ว
- ชำระเงินได้ทีละวิธีต่อบิล (เงินสด / บัตร / PromptPay) ยังไม่รองรับแบ่งจ่าย

```
  customer/   เว็บฝั่งลูกค้า
  components/ ส่วนที่ใช้ซ้ำ
  lib/        เรียก Supabase, offline queue, ฟังก์ชันช่วยต่าง ๆ
  auth/       ตรวจสิทธิ์ตามบทบาท
  i18n/
```
